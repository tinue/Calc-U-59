Getting started

FAQ

Concise answers to the questions that usually come up first.

Where do state files live?

They are regular .ti59, .ti58, or .ti58c text files. On Mac, the preset picker opens them from disk; on iPhone and iPad, use the built-in file picker.

What should I check first if a file opens wrong?

Check the partition, then the selected module, then the printer setting. Those three control the most visible parts of a loaded preset.

Can I see what the emulator is doing internally?

Yes. Use the debug pane: CALCULATOR for program state and live registers, CPU for the ROM instruction trace, and LOG for text output plus trace controls. For analyzing sequences, TRACE is more useful than the CPU tab.

How do I get a trace file?

Open the debug pane, switch to LOG, and turn TRACE on. The app writes a binary session file to the configured trace location. You can then export it and analyze it with read_trace.py.

What does the CALCULATOR tab show versus the CPU tab?

CALCULATOR shows the instruction that will execute next, with registers in their current state before it runs. CPU shows instructions that already ran, with registers in the state after each one. STEP and RESUME also work differently per tab and are only enabled in the tab that caused the current freeze — using them in the wrong tab is prevented.

My trace file is 190 MB. Is that normal?

Yes, for long sessions. But when you convert it to text with read_trace.py using the --clean and --skip-repeating flags, it compresses to a fraction of that size because the tool deduplicates repetitive loops.

Why does the display look different between models?

Calc-U 59 can start in TI-59, TI-58, or TI-58C mode. The model affects the startup state, memory layout, and the available controls.

Is there a faster way to read long printer output?

Yes. Switch the printer view to text mode, then copy or cut the strip on any build if you want a plain-text version quickly.
