# Shared C++ Layer (`Shared/`)

> **Provenance notice.** This document was generated by an AI (Claude) while
> moving the Swift app's non-GUI logic into `Shared/` and building the Qt6
> app on it. Like the other `reference/*.md` files it is best-effort and
> correct as of writing — the code wins where they disagree.

`Shared/` holds everything both frontends need that is neither hardware
emulation nor drawing. It sits between `Core/` (the emulated hardware, see
`CoreArchitecture.md`) and the two GUIs:

```
App/ (SwiftUI) ── Bridge/ (ObjC++) ──┐
                                      ├── Shared/ (C++17, std only) ── Core/
Qt6/app/ (Qt Widgets) ───────────────┘
```

- **C++17, standard library only** — no Foundation, no Qt, no iCloud. The
  root `CMakeLists.txt` builds it as C++17 (the Xcode project compiles it as
  gnu++17), so a C++20-ism fails the CMake build.
- **No locations.** `Shared/` never resolves where files live: it takes paths
  (`std::filesystem::path`) or a `ResourceReader` callback that returns a
  bundled file's text by name (Swift: `Bundle.main`; Qt: the `:/roms/` qrc).
  iCloud stays in `App/CardStorage.swift`.
- **Thread-safe where called across threads** (session, runner, sequencer,
  trace writer, freeze controller); the rest is plain value code.
- **Namespace `cu59`.** Headers include Core relatively (`../Core/...`).

## The runtime (`EmulatorSession`)

A frontend owns one `EmulatorSession` per machine (a model switch builds a
new one), forwards user actions to it, calls `tick()` at 60 Hz and receives
events through `EmulatorSession::Listener`.

| Thread | What runs there |
|---|---|
| Frontend UI thread | `tick()`, all user actions, arming freezes, drawing |
| Emulation thread (`EmulationRunner`) | The paced run loop, and every job posted with `post()` / `sync()` — warm-up, freeze-to-keycode, steps, state application, ASM entry — always after the loop has exited |
| Key sequencer lanes (`KeySequencer`) | KEYSTROKES playback and physical-keyboard taps, two independent lanes (a key press never cancels a script) |
| Key sequencer timer | Deferred releases (a key let go before its 100 ms minimum hold) |

**Listener callbacks arrive on the emulation or sequencer threads.** The
Swift app hops to the main queue (`SessionEventForwarder` →
`DispatchQueue.main.async`); the Qt app re-posts with
`QMetaObject::invokeMethod(..., Qt::QueuedConnection)`.

`sync()` waits for the job; call `stop()` first, or it waits for the run
loop. The frontend tells the session when it freezes (`setFrozen`) so key
playback stops waiting for an idle CPU that will never come.

## Tests and goldens

`tests/` (CTest target `CalcU59Tests`, run from the repo root) covers every
module, with the ROMs from `roms/`. Ports of Swift code are checked against
goldens produced by compiling the Swift original (`tools/goldens/`,
`tests/golden/`).
